This is the platform **outcome** page for **AI Fundamentals for Builders**. It is not a coding room. It is not checked with a proof checklist or in-lesson code runner.

## What this credential represents

The learner completed the AI Fundamentals for Builders course path and produced portfolio-oriented proof around:

- AI feature classification (automation, prediction, generation, guarded workflow)
- Models as parts of product systems, not naked engines
- Prompt contracts and prompt debugging logs
- Internal API boundaries (no learner-owned provider keys on the core path)
- Structured outputs and validation fallbacks
- Retrieval / RAG grounding with citations and uncertainty
- Tool routing and guarded agent stop rules
- Responsible AI release review (privacy, tiers, logging, escalation, rollback)
- A final AI Builder proof packet assembled from local Python practice

Practice for this course runs on the learner’s computer with Python 3: edit → save → run in a terminal. ASV Learn hosts the lesson text; your code runs in your own terminal, not inside the lesson page.

## Publication lock note

Once certificate issuance is published for this course, issuance should stay locked behind confirmed course completion. Learners should receive the final credential record only after the platform confirms requirements are complete.

## Conservative wording (required)

Use **Certificate of Completion** only.

Do **not** present this as:

- a degree or diploma
- a license or government accreditation
- a “certified engineer” professional license
- an employment guarantee
- a job-placement or salary claim
- proof that an embedded runner graded production-ready code

## How mentors should read the credential

The certificate means the learner finished the path and was asked to produce reviewable builder artifacts. Mentors should still open the portfolio proof (Stage 12) when making hiring or apprenticeship decisions. A certificate without artifacts is a completion signal, not a skills interview.

Keep the Stage 12 proof packet with any issued credential so a reviewer can see classification notes, prompt contracts, validation rules, retrieval boundaries, and the release-review checklist — not only a completion badge.
